# Amazon purchasing integration status

The app includes native Appstore SDK **3.0.9**, the required protected/exported ResponseReceiver, listener registration when a public authentication PEM is present, product-price discovery, purchase callbacks, purchase-update pagination, cancellation handling, account-bound cached entitlement storage and a `ReceiptVerifier` boundary. No fake adapter is selected in the running app. The fixture is located exclusively in `app/src/debug`; release sources cannot use it.

`verificationConfigured` remains false. The app selects the real `SupabaseReceiptVerifier`; its native SDK/Cloud Sandbox component integration now passes. Checkout is blocked pending production credentials, permanent Auth setup, abuse controls and full adapter acceptance. Neither tapping purchase nor restore enables premium yet.

The authenticated Supabase `routinenest-verify-receipt` function is deployed ACTIVE, version 6, to the user-selected free **lanray07's Project** (`guigiqacxpvcxrnajvlz`). It requires a user JWT (`verify_jwt=true`) and confirms the principal through Supabase Auth. Existing booking tables were not changed. Anonymous sign-ins were temporarily enabled for the approved tests, then restored disabled and verified after reload; three own test accounts were removed. A separate private rate-limit table and service-role-only RPC were added for RoutineNest. Only the public URL and publishable key are included in Android. No service-role/secret key belongs in the client.

Distributed verification limits allow 60 requests per authenticated subject and 600 globally per ten-minute fixed window. HMAC digests identify subjects; the table does not store raw Auth identifiers or receipts. Missing configuration/database failures deny verification. Expired buckets become eligible for removal one hour after expiry and are removed on subsequent requests. RLS with no client policies is deliberate: clients cannot read or write this private table. Both the database probe and concurrent authenticated HTTPS requests allowed 60 validation requests and denied the 61st; client roles cannot execute the RPC. Seventeen Node tests pass with synthetic network responses. The deployed endpoint rejects missing/invalid JWTs with HTTP 401. Real authenticated request validation, Android Auth refresh and Amazon Cloud Sandbox receipt verification pass; production receipts remain untested.

Amazon now has an unsubmitted **ENTITLED** product draft, `com.routinenest.app.premium`, with twelve offered description locales, Premium icons and a proposed GBP 2.99 base price. Amazon generated the other marketplace prices. These are unpublished proposals, not a validated sales catalog. See `amazon-iap-draft-evidence.json`.

The deployed JavaScript handler and independent Python reference policy match receipt/SKU/ENTITLED/cancellation data, reject production test transactions, bound responses, disable redirects and separate retry/revocation/configuration failures. Twelve Python policy tests and seventeen JavaScript endpoint/rate-limit tests passed with synthetic responses. The live endpoint rejected missing and invalid tokens with HTTP 401. A real App Tester receipt has been checked through Cloud Sandbox; no production receipt has been checked. Amazon binds the receipt/user pair through its successful request path, not a nonexistent `userId` JSON field. Supabase Auth identifies the app session; this is not a persistent identity mapping to the Amazon account.

The Android client checks subject/account/receipt/SKU/expiry over HTTPS, refreshes Auth sessions and encrypts tokens with Android Keystore AES-GCM. The adapter persists an authenticated encrypted lease with a six-hour server expiry, verifies the current Amazon account before restoring cached access, ignores stale callback results and periodically checks cached expiry. Restore waits for the authoritative account callback. Device clock changes, pagination/reconciliation and fulfillment retry still require real purchase tests.
